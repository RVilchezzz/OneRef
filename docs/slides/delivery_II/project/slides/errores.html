Lesson: unit tests with fake data passed 20/20 while the real file broke the first line. Run on real data early.

Honest list of what went wrong. First, our data loader had only been tested with fake data and failed on the real file because MMAD names the discrimination subtask Anomaly Detection; it is fixed and tested. Second, the threshold that turns the expert's distance into a yes/no vote was set for another scale, so with DINOv3 it never fires; we already recalibrated it on dev with a single global threshold: balanced accuracy goes from 0.49 to 0.61, measured on the same dev images, so it is optimistic. Third, in GoodsAD the only reference is often another product, so the expert is at chance there and must weigh less. Fourth, the 8B readers have not run yet: that is the critical path for this week.
